# Эмулятор командной оболочки

## Общее описание

Консольный эмулятор UNIX-подобной командной оболочки,
реализованный на Python.

На первом этапе реализован минимальный прототип приложения
с интерактивным режимом работы. Реализовано формирование
приглашения на основе имени пользователя и имени компьютера,
разбор введённых команд с поддержкой аргументов в кавычках,
обработка ошибок и команды-заглушки `ls` и `cd`, а также
команда `exit`.

На втором этапе добавлена возможность настройки приложения
с помощью параметров командной строки и конфигурационного
файла в формате TOML. Также реализован запуск стартового
скрипта с командами эмулятора перед переходом в
интерактивный режим.

На третьем этапе реализована виртуальная файловая система
(VFS). VFS загружается из XML-файла и хранится в памяти
эмулятора без распаковки или изменения исходных данных.
Для хранения бинарных данных используется Base64.
Добавлена обработка ошибок загрузки VFS, а также сценарии
запуска с различными вариантами виртуальной файловой системы.

На четвёртом этапе реализована логика команд `ls` и `cd`
для работы с VFS, а также добавлены команды `find` и `tac`.
Команда `ls` поддерживает флаги `-a`, `-l`, `-h` и любые их
сочетания.

## Структура проекта

* `src/main.py` — запуск, конфигурация, REPL и стартовый скрипт;
* `src/vfs.py` — загрузка и хранение VFS в памяти;
* `src/commands.py` — реализация команд эмулятора;
* `tests/` — тестовые файлы и сценарии проверки;
* `run.bat` — запуск приложения в Windows;
* `.gitignore` — список файлов и папок, исключённых из репозитория;
* `README.md` — описание проекта;
* `config.toml` — конфигурационный файл приложения.

## Основные функции

`get_prompt()` — формирование приглашения командной оболочки
на основе имени текущего пользователя и имени компьютера.

`parse_input()` — разбор введённой пользователем команды
с помощью `shlex.split()`, включая корректную обработку
аргументов, заключённых в кавычки.

`parse_arguments()` — обработка параметров командной строки:
пути к VFS, стартовому скрипту и конфигурационному файлу.

`load_config()` — чтение конфигурационного файла в формате
TOML и обработка ошибок его чтения.

`get_config_value()` — получение параметров из конфигурационного
файла и проверка их наличия.

`resolve_settings()` — формирование итоговых параметров
приложения с учётом приоритета параметров командной строки
над параметрами конфигурационного файла.

`print_settings()` — вывод итоговой конфигурации приложения
при запуске.

`load_vfs()` — загрузка виртуальной файловой системы из XML-файла
и построение её представления в памяти. Исходный XML-файл
не изменяется и не распаковывается.

`execute_command()` — выполнение поддерживаемых команд
эмулятора и определение необходимости завершения программы.

`execute_line()` — разбор и выполнение одной команды.

`run_startup_script()` — чтение и выполнение команд из
стартового скрипта. При возникновении первой ошибки выполнение
скрипта прекращается. Команда `exit` также завершает выполнение
эмулятора.

`run_repl()` — интерактивный режим работы с пользователем.

`ls`, `cd`, `find`, `tac` — команды работы с VFS
(описаны в разделе «Команды»), реализованы в `src/commands.py`.

`exit` — завершение работы эмулятора.

Также реализована обработка неизвестных команд,
синтаксических ошибок при разборе строки, ошибок чтения
конфигурационного файла, ошибок выполнения стартового
скрипта и ошибок загрузки VFS.

## Настройки

Приложение поддерживает три параметра командной строки:

* `--vfs-path` — путь к XML-файлу виртуальной файловой системы;
* `--startup-script` — путь к стартовому скрипту;
* `--config` — путь к конфигурационному файлу в формате TOML.

Параметр `--config` является обязательным.

Конфигурационный файл содержит параметры:

```toml
vfs_path = "vfs/minimal.xml"
startup_script = "tests/startup.txt"
```

Если параметр `--vfs-path` или `--startup-script` указан
в командной строке, используется значение из командной строки.
Если параметр не указан, его значение берётся из
конфигурационного файла.

Таким образом, параметры командной строки имеют приоритет
над параметрами из конфигурационного файла.

При запуске приложение выводит итоговую конфигурацию:

```text
Emulator configuration:
VFS path: vfs/minimal.xml
Startup script: tests/startup.txt
Config file: config.toml
```

После чтения конфигурации приложение загружает указанный
XML-файл виртуальной файловой системы в память.

## Виртуальная файловая система

На третьем этапе VFS представлена в виде XML-файла.

Пример структуры VFS:

```xml
<vfs>
    <directory name="home">
        <directory name="user">
            <file name="hello.txt">Hello</file>
        </directory>
    </directory>
    <file name="readme.txt">Read me</file>
</vfs>
```

В примерах и тестах содержимое файлов хранится в Base64
(`encoding="base64"`):

```xml
<vfs>
    <file name="welcome.txt" encoding="base64">TmVzdGVkIFZGUyBleGFtcGxlLgo=</file>
    <directory name="home">
        <file name="todo.txt" encoding="base64">UmV2aWV3IHRoZSBWRlMgc3RhZ2UuCg==</file>
    </directory>
</vfs>
```

XML описывает каталоги и файлы виртуальной файловой системы.
Вложенные элементы позволяют создавать несколько уровней
вложенности.

Все данные VFS загружаются в память. Физическая файловая
система операционной системы не используется для выполнения
операций над содержимым VFS.

Бинарные данные файлов могут храниться в XML в формате Base64
и декодируются при загрузке виртуальной файловой системы.

Файл без атрибута `encoding` читается как обычный текст UTF-8.

## Команды

`ls [-a] [-l] [-h] [путь]` — вывод содержимого каталога
(по умолчанию текущего). Если указан файл, выводится только он.

* `-a` — показывать скрытые элементы (имена на `.`), а также
  `.` и `..`;
* `-l` — подробный формат: права, размер в байтах и имя;
* `-h` — размеры в удобном виде (`1.8K`), действует вместе с `-l`.

Флаги можно объединять в любом порядке и количестве:
`-la`, `-hla`, `-alh`, а также указывать раздельно: `-l -a -h`.
Элементы выводятся в алфавитном порядке.

`cd [путь]` — смена текущего каталога VFS. Без аргумента и
для `~` выполняется переход в корень VFS. Поддерживаются
абсолютные и относительные пути, `.` и `..`.

`find [путь] [-name шаблон] [-type f|d]` — рекурсивный поиск
в VFS, начиная с `путь` (по умолчанию `.`). `-name` — шаблон
имени (`*`, `?`, `[...]`), `-type` — только файлы (`f`) или
каталоги (`d`). Пути выводятся в том виде, в котором
указано начало поиска, элементы внутри каталога отсортированы.

`tac файл...` — вывод строк файлов в обратном порядке.

Пример:

```text
root@host:~$ ls -lh
-rw-r--r-- 1.8K big.txt
drwxr-xr-x 4.0K home
-rw-r--r--   19 lines.txt
root@host:~$ find /home -name "*.txt"
/home/student/documents/report.txt
root@host:~$ tac lines.txt
third
second
first
```

## Варианты VFS

Для проверки загрузки используются несколько вариантов
виртуальной файловой системы.

Минимальный вариант содержит корневой каталог и один файл.

Вариант с несколькими файлами содержит несколько файлов
и каталогов на одном уровне.

Вложенный вариант содержит не менее трёх уровней вложенности,
например:

```text
/
└── home/
    └── user/
        └── documents/
            └── file.txt
```

Также предусмотрены сценарии с отсутствующим или некорректным
XML-файлом для проверки обработки ошибок загрузки VFS.

## Стартовый скрипт

Перед переходом в интерактивный режим приложение выполняет
команды из указанного стартового скрипта.

Команды отображаются на экране вместе с приглашением,
имитируя ввод пользователя.

Например, файл `startup.txt`:

```text
ls
cd "test directory"
exit
```

приводит к выполнению соответствующих команд.

При возникновении ошибки выполнение стартового скрипта
прекращается на первой ошибочной команде.

Если стартовый скрипт содержит команду `exit`, выполнение
эмулятора полностью завершается и интерактивный режим
не запускается.

На третьем этапе стартовые сценарии также используются
для проверки запуска приложения с различными вариантами VFS
и обработки ошибок их загрузки.

## Тестирование этапа 4

Файл `tests/vfs_student.xml` содержит VFS с тремя уровнями
вложенности, скрытыми файлами, пустым каталогом и файлом
размером более 1 КБ (для `ls -h`).

* `tests\test_stage4.bat` — запускает стартовый скрипт
  `tests\stage4\startup_stage4.txt` со всеми режимами `ls`, `cd`,
  `find`, `tac`;
* `tests\test_stage4_errors.bat` — последовательно запускает
  скрипты `tests\stage4\startup_err_*.txt` (по одному на `ls`,
  `cd`, `find`, `tac`). В каждом одна ошибочная команда, на
  которой скрипт останавливается.

## Запуск

Windows:

```bat
run.bat
```

Для запуска с конфигурационным файлом:

```bat
run.bat --config config.toml
```

Также приложение можно запустить напрямую:

```bat
python src\main.py --config config.toml
```

Параметры командной строки можно задавать непосредственно
при запуске:

```bat
python src\main.py --config config.toml --vfs-path vfs\minimal.xml --startup-script tests\startup.txt
```

При этом значения `--vfs-path` и `--startup-script` из
командной строки имеют приоритет над значениями из
`config.toml`.

Для проверки различных вариантов VFS используются
отдельные `.bat`-сценарии из каталога `tests/`. Они запускают
эмулятор с различными XML-файлами VFS, в том числе с
минимальной, содержащей несколько файлов и вложенной
виртуальными файловыми системами.

## Обработка ошибок

Если конфигурационный файл не найден или содержит
некорректный TOML, приложение сообщает об ошибке:

```text
shell: config error: ...
```

Если стартовый скрипт не найден или не может быть открыт:

```text
shell: startup script error: ...
```

Если во время выполнения стартового скрипта встречается
неизвестная команда:

```text
shell: command not found: unknown
shell: startup script execution failed
```

После первой ошибки выполнение стартового скрипта
прекращается.

Если XML-файл VFS не найден:

```text
shell: VFS error: ...
```

Если XML-файл содержит некорректную структуру:

```text
shell: VFS error: ...
```

Ошибки загрузки VFS не приводят к изменению или удалению
исходного XML-файла.

Если обязательный параметр `--config` не указан,
ошибка обрабатывается стандартным механизмом `argparse`.

## Сценарии проверки

На третьем этапе предусмотрены сценарии запуска,
проверяющие различные способы работы приложения:

1. Запуск с VFS из конфигурационного файла.
2. Запуск с VFS, указанной через `--vfs-path`.
3. Запуск с минимальной VFS.
4. Запуск с VFS, содержащей несколько файлов.
5. Запуск с VFS с несколькими уровнями вложенности.
6. Запуск с отсутствующим VFS-файлом.
7. Запуск с некорректным XML-файлом.
8. Выполнение стартового скрипта с командами предыдущих этапов.
9. Остановку стартового скрипта при первой ошибке.
10. Завершение эмулятора через `exit`.

## Пример

Запуск:

```text
python src\main.py --config config.toml
```

Вывод конфигурации:

```text
Emulator configuration:
VFS path: vfs/minimal.xml
Startup script: tests/startup.txt
Config file: config.toml
```

После этого загружается XML-файл виртуальной файловой системы
и выполняются команды стартового скрипта.

Пример структуры загруженной VFS:

```text
/
├── readme.txt
└── home/
    └── user/
        └── hello.txt
```

В интерактивном режиме команды работают с загруженной VFS:

```text
username@hostname:~$ ls
home
readme.txt

username@hostname:~$ cd home/user
username@hostname:~/home/user$ ls -l
-rw-r--r-- 5 hello.txt

username@hostname:~/home/user$ unknown
shell: command not found: unknown

username@hostname:~/home/user$ exit
```

Проект использует только стандартные библиотеки Python.
